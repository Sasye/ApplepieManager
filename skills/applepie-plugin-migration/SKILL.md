# Applepie 插件迁移

保留插件原有功能，按实际操作接入 SDK 的加载、Hook 和资源管理。评估任务输出迁移差异；实施任务完成代码、构建及验证。

## 定位当前接口

先确定 `PLUGIN_ROOT`（待迁移源码）、`SDK_DIR`（含 `applepie.h` 的目录）及实际构建入口。优先使用用户给定路径，再查当前工作区；技能安装目录不等于 SDK 所在目录。缺少 SDK 时可以先盘点插件，但不要凭记忆编造接口。

必读 `SDK_DIR/README.md`、`applepie.h`、`applepie_client.h` 和 `examples/minimal_plugin.cpp`。按需再读：

| 场景 | SDK 文件 |
|---|---|
| native 入口、特殊 ABI、错误状态、原调用异常 | `applepie_native.h`、`applepie_seh.h` |
| 终末地常用共享 Hook | `applepie_endfield_adapters.h`、`applepie_endfield_contracts.h` |
| 指针槽替换 | `applepie_pointer_scope.h`，以及 `applepie.h` 中的 Pointer 服务 |
| 游戏线程、窗口命令、游戏写入、停用恢复 | `applepie.h` 中 Runtime、Window、Write、Lifecycle 服务及 SDK 对应说明 |

本文以 Windows x64、MSVC C++17 客户端为基线。纯 C 或特殊入口可直接使用公开 C API。接口及限制以实际 SDK 版本为准。

公开 ABI 使用 SDK 定义的固定 POD、句柄和函数指针，保持其结构大小与 pack；不要跨 DLL 传递 STL 对象、C++ 异常或 CRT 分配所有权。

沿用项目已有的 SDK 依赖方式，核对构建实际引用的版本；不要复制出一份私有 Core 或修改公共结构体来掩盖版本不匹配。

## 先做一张操作清单

读取插件入口、初始化、Hook 安装、原函数调用、线程、停用/恢复和构建依赖。搜索 `MH_`、`Detour`、`VirtualProtect`、`InterlockedExchangePointer`、`SetWindowLongPtr`、`SetWindowSubclass`、`DllMain`、`LoadLibrary`、`FreeLibrary`、线程入口及直接赋值的函数指针槽；搜索结果是线索，还要追踪真实调用链。

逐项记录：目标及地址来源、真实原型、原函数调用次数/阶段、返回值及输出参数、线程局部错误状态、执行线程、读写对象、原值/恢复条件、共享需求。按以下边界迁移：

| 原操作 | 迁移方式 |
|---|---|
| 不依赖游戏运行时的文件、网络、音频、独立 UI、纯数据运算 | 保留插件实现；若支持停用，由插件取消和排空自有任务。无需凭空引入 Runtime、Actor 或写权 |
| 解析地址、解析 icall、直接调用函数 | 地址解析仍归插件；直接调用本身不是安装 Hook。调用游戏或托管运行时仍需核对运行时、线程和对象生命期；修改共享状态时另核对写入契约 |
| 一般函数入口 Hook | `applepie::NativeHook<Tag, Function>` |
| 特殊调用约定/返回 ABI、目标提前筛选、手写入口 | `applepie::Hook` 管安装，保留准确入口、业务准入及 Original proxy |
| 多插件共享同一目标 | `applepie::SharedHook` 加明确契约；标准终末地目标可选用现成适配器 |
| 修改函数指针 slot | 核对 Pointer 服务支持范围后，由 Core 管申请、条件替换和恢复；临时 wrapper 使用 `APH_WithPointerPatch` |
| 公共游戏窗口链、发往游戏窗口的命令 | 使用 Window 服务；插件自己的独立窗口不必迁入公共窗口链 |
| 游戏共享状态的字段、骨骼、动画或相机写入 | 保留业务写入，使用与该资源匹配的 Runtime/Write 契约；记录原值并实现恢复，不支持的写入域明确列为缺口 |
| 中间指令 Hook、匿名/JIT 目标、任意代码补丁、不支持的 slot 或新写入域 | 列出当前 SDK 的具体缺口，在授权范围内适配底层能力；不能假装通用 Hook 已支持，也不能退回私有补丁后端后宣称共存完成 |

不要仅将 `MH_CreateHook` 文本替换成 Request。一个插件可以同时使用多种路径，SDK 客户端和底层 C API 可以混用。

把用户已确认的旧版功能与共存组合作为回归基线，并区分实测事实、源码推断和未验证项。检查相关插件的同址入口与调用顺序，不能因为新框架的默认独占请求冲突，就断言旧版无法共存。跨仓库评估不自动授权修改其他插件；需要双方对齐的契约应明确记录，只实施授权范围内的部分。

## 接入加载与生命周期

1. 以最小示例为起点，导出只读 DATA `APH_PluginManifest`、`APH_Attach`、`APH_Enable`，使用稳定且唯一的插件 ID。只声明真正需要的能力；无 Hook 插件不要求 HOOKS。当前 GAME/GUI 是保留能力位，不因插件需要角色或 UI 就把它们列为必需，否则可能一直 WaitingCapabilities。
2. 让 DllMain 与静态初始化保持被动。代理仅引导 `plugin/applepie_manager.dll`，由 Manager 扫描业务 DLL。去掉插件自身的重复自动加载/安装链。
3. Attach 中创建模块期 `applepie::Client`，调用 `Attach(args)`，按需 `Service(table)` 并缓存服务表。支持异步启用/停用时登记 `RegisterLifecycle`。保留业务所需的旧 UI/元数据导出，但不能把旧 `AP_PluginDisable()` 的 bool 当作已排空证明。
4. Enable 中执行本次启用准备。只在真实支持时声明 `APH_PLUGIN_LIFECYCLE` 和 `APH_PLUGIN_LATE_LOAD`；仅确有常驻观察需要时使用 `APH_PLUGIN_MODULE_OBSERVER`，不要照抄包含所有标志的宏。LATE_LOAD 和 MODULE_OBSERVER 均要求同时声明 LIFECYCLE。仅 Hook 创建/绑定事件可能漏掉安装前已经存在的状态：按需结合当前状态发现与后续事件，并处理两者交错、重复和代次失效。不能靠固定延时、重放有副作用的创建函数，或要求用户触发不相关操作来假装晚加载完成；没有安全发现路径时明确列出缺口。
5. 同步完成返回 OK；异步返回 Pending，由插件自己的初始化执行单元持有**本次 epoch 的副本**，最终 `CompleteEnable(epoch, result)`。过期任务不得修改新一轮状态。初始化失败或取消也要有终点，不能无限等待自己才能触发的事件。

SDK 不隐式创建线程。独立工具插件的启用不应被不相干的角色或 Runtime 就绪条件阻塞。

区分模块期初始化与每次启用：检查 `once_flag`、单例锁、初始化标志、线程和取消事件的寿命。再次 Enable 不能被旧守卫短路后误报成功；旧任务排空后才重置或替换其取消事件和上下文。初始化失败或取消后，按真实可恢复状态决定能否重试。

## 迁移 Hook，保留特殊语义

- Request 使用模块期唯一 key 和稳定的注册对象。`NativeHook` 的每组 Tag/签名只绑定一个目标；不能用循环覆盖同一份 entry/context/original。模块身份检查不证明实际函数原型正确。
- 保留已验证的调用约定、隐藏 `MethodInfo`、结构体返回缓冲区、按值参数和返回值。反射匹配还要核对实例/静态、参数及返回类型、引用/值类型和适用的泛型形式；名称与参数数量相同不足以确认原型。签名字符串只用于一致性校验，不会生成正确的 ABI。
- 目标 API 若使用 `GetLastError()`、`errno` 等线程局部错误状态，按其 API/CRT 契约保留。包装器前置操作不能污染目标所需的输入状态；在 original 或替换业务返回后捕获其有效错误状态，完成计数、回调和清理后再恢复。不能无条件清零或恢复调用前的值。当前 `NativeHook` 未承诺保留这些状态，需核对实现，必要时使用 `Hook` 加手写入口或在授权内补足 SDK；仅在业务回调内保存不足以保护外层清理。
- 请求接受不等于激活完成。由初始化线程或已有控制执行单元推进 `Advance()`，仅 OK 表示完成；Pending/Busy 稍后处理。游戏、窗口和 native 回调中不等待安装或排空。
- original 和入口上下文必须在激活前发布。使用手写入口时，插件额外暴露给业务的 Original proxy 也要按原有顺序发布。只有相关 Hook 全部就绪且业务校验通过后才开放组内写入；可使用 `automatic_ready=false`，或保留已有 group-ready 机制。
- `NativeHook::Original(...)` 是受管原调用入口。独占业务可按原设计替换原行为；要求透传的路径保持一次 original，不重放、不因迁移改返回值。保留原有提前筛选：当前通用 `NativeHook` 没有参数级筛选入口，不能删除插件的廉价 POD/参数 predicate，换成所有调用都进入昂贵的业务准入。
- 新目标直接走通用请求，无需加进 Core 的游戏函数白名单。需要共享时，各方必须约定完全一致的真实 ABI、contract/version、payload 和 original policy；地址相同不能代替语义一致。独占冲突必须明确失败，不能私自再安装一次。
- 入口跳转也可能是原生导出/导入跳板，不能仅凭首条指令认定外部补丁。由 Core/后端处理请求入口；根据实际错误阶段、claim 和地址证据判断失败，不盲目追跳改目标或把安装失败当成可忽略的拒绝。
- 同址 Hook 若都透传 original 一次再观察参数/结果，优先评估共同的 Shared 契约，并核对各方是否已采用；不要因返回类型非 void 就自动选独占。仅改一方、分别改成不同契约，或保留另一方私有 MinHook，都不算共存迁移完成。若旧链存在返回值变换、顺序依赖或短路，先确认这些语义能否表达，不能以放宽冲突检查来拼接。
- 先检查共享契约能否表达原行为。当前 Shared 只有 original 恰好一次，以及 `APH_CONTROLLED_VOID` 下唯一 controller 抑制 void original 的策略；不提供通用的非 void 短路返回或返回值仲裁。需要这类语义时，使用能保留行为的独占请求并明确冲突，或列出扩展契约的需求；不能为套用 Shared 强行执行原本应跳过的 original、伪装 void 签名或删除替换分支。
- 系统/运行库 Hook 还要检查 Core、加载器、日志和插件辅助函数是否经过目标入口。沿实际调用链核对重入、锁顺序及错误状态；仅有同 Hook 递归标志不证明整条调用链可安全重入。
- 可选适配器包括 `SetMainI32`、`SetMainBool`、`BipedIK`、`SMCUpdate`、`MorphJob`、`SpecialMorphJob`、`CreateBindingByActionId`，以实际 SDK 提供项为准。只在原型与契约匹配时使用；其他插件无需包含它们。Job 的 AFTER 是调度函数返回，不代表作业完成；BipedIK 只有明确登记的 controller 可以抑制 original。输入绑定适配器保留原返回值，不负责持有委托或发现安装前的绑定。
- 共享入口中区分业务 listener 与模块期 observer。目标发现、线程认证和退出保护按真实需要保留；业务停用后，provider 的入口、original 和必要常驻观察仍须服务其他成员。订阅本身不授予游戏写权。
- 业务 listener 按自身能力准入。纯参数/结果观察不应被不相关的动画、相机或当前角色条件阻塞；也不能为绕过这类条件改成停用后仍执行的模块期 observer。后续解引用对象、调用游戏方法或写入共享状态时，再落实对应的生命期、线程及资源契约。
- `Subscription::Close()` 返回 Pending 时保留句柄和 callback context，确认关闭后再为新 epoch Listen。`Retire()` 是永久释放申请，不是日常热停用；不要在每次 Disable 中释放 native claim，再在 Enable 中重复安装。

手写入口保留 `enter_call → 准确原型调用 → __finally leave_call` 及原调用阶段。异常按 SDK 契约记录和传播；不要新增吞掉所有异常、重试 original 或伪造成功的 catch-all。`/EHsc` 的 C++ catch 不能替代 SEH；清理计数不要仅依赖 C++ 析构。SEH 不保证挽救错误写入、original 异常、堆栈损坏或死锁。

## 按需处理游戏运行时、写入与 slot

不涉及这些操作的插件跳过本节。

**直接调用运行时：** 按实际调用链区分独立 I/O 与借游戏服务完成的网络、音频或其他业务，后者即使没有 Hook 或共享字段写入也不能跳过运行时检查。线程注册/attach 不证明任意方法允许在该线程调用；核对方法的线程要求、异常通道及对象生命期。初始化、连接/会话重建和运行时退出应有就绪与缓存失效条件，固定等待时间不作就绪证明。可复用已声明且验证过的运行时服务，不能把另一可选业务插件恰好启用当作就绪条件。

**启动就绪：** CoreReady、DLL/导出存在、非空运行时指针或 `probe_open` 允许访问，均不证明 GC、线程注册等初始化已完成。首次 attach、对象或元数据访问前，使用按当前运行时实现核验、在未就绪阶段也安全的探测或完成通知。getter 可能隐式分配对象或初始化，不能凭名称认定只读。等待须可取消、有超时，并覆盖已启动后的晚加载；不要主动初始化游戏的 GC 或依赖 SEH 挽救运行时的致命终止。

**跨回调引用：** 事件 payload、字符串、委托及结果指针默认只在声明的借用期间有效。确需长期使用时，采用对应运行时的持有方式，保存可释放的 handle，并同步替换、使用与释放；仅把裸指针放进全局变量不足以保活。GC root/引用计数只解决存活，不保证绑定、场景、会话或 native 对象仍有效；同时记录适用的身份/代次并在重绑、停用和退出时失效。旧操作尚需该对象收尾时，保留独立清理上下文至排空，不能被新绑定覆盖。

写入分类依据资源所有权和可观察影响。插件创建且尚未共享的临时对象初始化，不因使用 setter/字段写入 API 就自动需要 Animation/Camera lease；一旦操作游戏共享状态，必须核对对应资源契约。缺少合适契约时报告具体缺口，不能假借已有写域获得权限。

**线程与写权：** Runtime Live、游戏线程和当前目标都需要实际证据；GUI、窗口回调或共享订阅不是证明。当前 Animation 与 Camera 是两个独立的全局写域，未提供按角色划分的锁或任意内存补丁接口；其他资源需要对应的写入契约。

明确的播放/冻结/相机接管动作申请 lease；每次真实写入还要 `enter → 业务 → __finally leave`，多域按进入顺序逆序退出。携带当期 owner epoch、runtime epoch 和 target generation。原生 worker 获准处理 POD 不代表可以在任意线程调用 Unity/IL2CPP。异步命令复制输入并保留代次，执行前重验；不能借用 UI/网络线程栈上的指针。

**slot：** 保留编译裁切场景所需的每条原 wrapper 路径，逐条登记，不能以“可能直接调用”为理由删掉回退。保存 slot 地址、明确的 expected/replacement、模块身份和作用域，不能把任意当前值当作新的 expected。临时替换用 `APH_WithPointerPatch` 配对申请、原 wrapper 调用及 finally 恢复；持久替换也要有明确的 release 生命周期。

当前 Pointer 服务要求 slot 位于已加载 PE 的对齐、可写非执行数据页，expected/replacement 位于已加载 PE 的可执行页，并要求有效的 Runtime/目标/线程票据；不负责修改页保护。堆上 vtable、副本表、只读槽或不具备这些票据的通用插件不能直接套用。返回冲突、Expected 不匹配或不确定恢复时保留证据和占用，不直接写内存绕过 Core。

Core 按 slot 地址登记并条件恢复，只能协调已接入者。它不能自动阻止游戏线程或重入调用在临时 Get→Set 替换期间访问该槽；仍需证明调用阶段和并发边界。wrapper 异常不可重试，恢复后还要拒绝旧目标/旧 epoch 的结果。

## 实现真正可恢复的逻辑停用

正常流程是 `Active → Disabling → Disabled`，DLL 常驻；更新 DLL 需重启进程。Attach 只一次，重新启用使用新 epoch 并续接业务订阅/窗口路由。

- `disabling` 只取消自有任务、停止新生产、更新标量和 UI 状态。游戏对象恢复放在已验证且适合该业务的 checkpoint；无游戏资源的工具可在控制侧完成 domains=0 的恢复。
- Core 在途计数不自动覆盖插件自有 worker、定时任务或异步 I/O。用同一锁或正确的原子协议协调任务准入、计数和关闭，不能把单次布尔检查或 `volatile` 当作排空证明；共享配置也需同步访问。取消应能唤醒初始化及周期等待，不能依赖 DllMain 卸载、强杀线程或等完整业务周期后才停用。
- 等待真实在途工作结束，再按原顺序恢复修改、释放 root、清理缓存。恢复前保留原值及对象身份；不能先清空缓存，之后才发现失去了恢复所需数据。
- 成对业务（按下/释放、开始/结束、获取/归还）分别记录外部输入状态与已成功提交的逻辑状态。停用、重绑、配置切换和适用的失焦路径也要处理未完成的配对，不只清空布尔位。先停止新动作，再用仍有效的原绑定和合法执行阶段收尾；不能对新绑定补旧释放，也不能因异常或结果未知重复提交。无安全收尾条件时记录未完成状态并按生命周期报错。
- 区分可恢复的本地修改与已经提交的外部操作。停用应停止后续提交、取消可取消任务并确认在途结束，不能宣称已撤销不可回滚的副作用，也不能因结果不确定自动重放操作。
- `restore` 只有在相应操作实际完成后才返回 OK。Pending、线程不对、超时、读回失败或对象身份失效不能伪装成功；失败/不确定时保留记录与占用。一次清理只能确认本次捕获的 domain/lease/epoch，不能顺便清掉同时才进入 Releasing 的其他域。
- 未获写权、旧 epoch、旧目标和已经关闭的入口不得继续写。保留 Runtime stop/shutdown 等插件特殊边界；停止播放与停用插件不一定是同一个操作。
- 高频回调不增加 `Service`、安装查询、资源表扫描或分配。保留已有目标筛选、快速 probe 和缓存失效规则；不能用永久缓存“曾经有效”省掉必需的当期检查。

## 验证与交付

先构建目标插件。删除私有 Hook 后端依赖前，核对所有活动入口都已迁移；检查编译/链接命令、源码和 map/符号，不能只看 DLL import 表，因为 MinHook 可能静态链接。仅清理已无用途的依赖，保留第三方许可和必要源文件。

SDK 的可编译基线在 `examples/minimal_plugin.cpp`。在完整 ApplepieManager 仓库根目录可运行：

```bat
sdk\examples\build.bat
sdk\examples\build.bat /verify
```

前者只需 SDK 和 MSVC，后者还依赖 Manager 源码及其 MinHook 后端。这些是基线检查，不能替代待迁移插件自身的验证。

按改动选择能观察实际行为的离线检查：

| 涉及改动 | 需确认的行为 |
|---|---|
| 加载、异步启用、后台任务 | Manifest/导出有效；晚加载能发现当前状态；启动/周期等待可取消；关闭准入与任务启动交错时仍正确排空；旧 epoch 完成被拒绝；初始化失败、停用后的再次启用符合约定 |
| 独占/手写 Hook | 实际安装、准备、原调用/返回 ABI、输出参数及适用的错误状态保持；启用、透传、停用和重入路径均不失真；原异常不重放；手动 ready、回滚和目标筛选仍有效 |
| 共享 Hook | 已知共存组合及两种加载顺序；同址只有一个 native provider；签名/契约冲突被拒；参数、返回值、原调用次数与顺序保持；provider 停用后仍服务成员；成员续订与 controller 权限正确 |
| 直接调用游戏/托管运行时 | 分阶段模拟模块/导出可用而 GC/线程设施尚未就绪，确认提前的 attach、对象及元数据调用为零，探测本身也安全；覆盖就绪后继续、等待中取消/退出/超时和晚加载；核对线程准入、异常通道、缓存失效及资源契约 |
| 事件捕获、跨回调引用及成对动作 | 安装前已存在状态能按支持范围发现；重绑/失效不使用旧引用；对象持有和释放配对；动作未结束时停用/重绑/再启用能正确收尾，失败不假报完成 |
| slot | 全部原路径保留；预期值错误、同槽竞争、异常退出、条件恢复失败及旧代次按约定处理 |
| 游戏写入/停止 | 停止后再次操作、清理等待、恢复失败保留、不同域冲突及旧目标命令失效 |
| 高频入口 | 用调用计数确认没有新增服务获取/安装轮询；非目标调用不进业务，必要 original 和 Core 计数仍配对 |

必要的故障注入在独立宿主中执行，不在真实游戏中故意制造异常。离线通过不等于游戏 ABI、线程时序、视觉或帧率已验证；有游戏操作时提供最小手测序列：首次/晚启用 → 原功能 → 停止 → 再次操作 → 停用/再启用 → 与相关插件共存，按功能选择切目标/退出检查。

在最终答复或项目现有记录中交付：操作清单的迁移结果、保留的特殊路径、仍缺失的能力、本次构建/测试结果、产物路径及未验证的游戏行为。删掉功能或永久禁用某条路径不能视为完整迁移。迁移授权本身不包含自动部署、注入/启动游戏、提交或发布；已有明确授权则按其范围执行，不额外重复确认。
